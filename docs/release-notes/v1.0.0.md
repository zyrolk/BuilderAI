# BuilderAI v1.0.0 Release Notes

## Summary

BuilderAI MVP v1.0 connects the existing governed Project Brain pipeline to the existing workspace
through a server-only orchestration boundary. The release candidate now supports configuration-selected
OpenAI Responses or Google Gemini adapters without redesigning a core contract or adding dynamic
routing, UI features, Git behavior, deployment behavior, rollback, or multi-user behavior.

## Capabilities

- Canonical Project Brain and versioned documentation discovery, validation, analysis, and summary.
- Task-scoped, prioritized, deduplicated, size-bounded Context and Prompt Packages.
- Isolated non-streaming OpenAI Responses and Google Gemini adapters with structured response
  enforcement and server-only configuration selection.
- Deterministic response normalization, checksums, manifest, change planning, conflicts, risks, and
  explicit approval.
- Protected, root-scoped create, update, and delete application with complete preflight and results.
- Fixed Project, Dependency, Build, and Test verification with one validated final report.
- Responsive accessible dashboard and workspace with fail-closed configuration behavior.

## Hardening delivered

- Same-origin loopback route restriction, JSON and payload bounds, generic errors, and no-store policy.
- Opaque expiring server-held plans, single-flight claims, idempotent completion replay, and no trust in
  browser-supplied plans.
- Root containment, ancestor symlink rejection, conditional file operations, fixed shell-free npm
  commands, reduced child environment, deadlines, output bounds, and redacted metadata.
- Correlated structured lifecycle diagnostics that exclude requests, source, provider payloads,
  credentials, command output, and system paths.

## Known limitations

- Local trusted single-operator profile only; no authentication, authorization, public hosting, or
  multi-instance coordination.
- In-memory preparations are lost on restart and are not distributed.
- Build and test scripts execute trusted project code without an OS sandbox or guaranteed no-network
  enforcement; process descendant termination is platform-limited.
- File application is conditional but not transactional; no rollback or Git recovery is supplied.
- One statically selected provider per local process and synchronous responses only; no dynamic routing,
  fallback, streaming, tools, files, images, background work, conversation persistence, telemetry,
  automatic repair, or deployment.

## Upgrade and reversal

Install from `package-lock.json` with Node.js 24 and npm 11. The runtime remains off until explicitly
configured. Set `BUILDERAI_LIVE_WORKFLOW_ENABLED=false` or remove it to return immediately to
review-only operation.
